1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
The StatGate monorepo is a multi-application government statistics platform
comprising 20+ first-party projects: a Flask analytics engine (frontend/), 9 Go
micro-services (backend, StatChat, StatCollect, StatSpatial, PMS, RMS,
StatGovernance, enterprise, stage_register/go-backend), 4 React SPAs, a Next.js
launcher (appluancher), a Node.js helpdesk (helpdesk-master), a monitoring
stack, a JupyterHub, 11 PostgreSQL bootstrap scripts, and an ODK Collect Android
fork (collect-master, 2189 files, vendored upstream v8.6). It also contains a
large amount of committed build/runtime debris: the bundled CPython runtime
frontend/Lib (5514 files) + frontend/.venv.bak (4665), ~68 .exe binaries,
.next webpack caches, logs, and .gocache.

The system is feature-rich but NOT production-safe in its committed state.

  CRITICAL
  1. Live secrets committed in plain text across the repo (root .env,
     secrets/, per-project .env, docker-compose fallbacks, Trino/Loki configs).
     Anyone with repo access can connect to every database and forge JWTs.
  2. JWT validation is BYPASSABLE in several services:
       - enterprise/core/middleware_security.go:230-238: when the JWT secret is
         unset, auth is skipped and client-supplied X-User-ID / X-Tenant-ID
         headers are trusted (full impersonation).
       - StatGovernance/backend/middleware.go:50: any token starting "demo_"
         authenticates as a Governance Officer; STATGOVERNANCE_REQUIRE_AUTH
         unset impersonates admin.
       - StatChat: STATCHAT_AUTH_REQUIRED defaults false => all routes open,
         every request attributed to user-001 (handlers.go:42-44,1124-1127).
  3. Helpdesk API has unauthenticated user-mutation endpoints
     (PATCH/DELETE/GET /api/users/:id, public /agents, open comments & video)
     and a public registration endpoint accepting any role => privilege
     escalation to admin; registration also returns the password hash in JSON.
  4. JupyterHub uses DummyAuthenticator with password "password".

  HIGH
  5. Hardcoded credential fallbacks in code (DB "postgres", shared JWT
     "statgate_field_secret_key_2026", meeting-room passwords).
  6. Default API keys "changeme" (StatCollect); default basic auth admin/password.
  7. Dynamic SQL via fmt.Sprintf in several handlers; parameter hygiene
     inconsistent (see section 5).
  8. Committed binaries/logs/caches (~200MB+) leak internals; phaseV_complete.txt
     dumps the full Gin route table.
  9. Cross-file configuration drift: port mismatches, DB-name mismatches,
     inconsistent secret fallbacks (section 6).

  MEDIUM/LOW
  - Missing input validation and error swallowing throughout.
  - Open CORS in helpdesk (app.use(cors())).
  - No per-tenant authorization in several read handlers.
  - Near-identical duplicated code across PMS/RMS/StatGovernance/Registry.

5. MEDIUM / LOW FINDINGS

M-01  STATCHAT CORS/SESSION HYGIENE
  - CORS allows any localhost port and same-host origins (handlers.go:1249-1271)
    with credentials - acceptable in dev, not in production.
  - WS endpoint accepts the JWT as a query param (handlers.go:1137-1138,
    frontend client.ts getWebSocketURL) - tokens can leak into proxy/server
    logs and browser history; the frontend strips the param (client.ts:38-47).

M-02  ANALYTICS AUTH GATING ONLY WHEN AUTH_REQUIRED
  frontend/app.py:215-228 require_registry_identity() and L171-172: with
  ANALYTICS_REQUIRE_AUTH=false (root .env:114) all /api endpoints are open;
  tenants default to tenant-alpha. dashboard/notebook/executive/semantic/abac
  pages are public. /api/notebook/execute (if ENABLE_NOTEBOOK_EXECUTION=true)
  executes Python - gated to non-production (notebook_service.py:5-7) but auth
  is not enforced on it in dev.

M-03  HELP DESK OPS ISSUES
  - index.js:32 app.use(cors()) - any origin.
  - ticketRoutes.js:25-43 hardcoded personal Gmail recipients; dual
    res.status() calls (200 in callback + 201 after) cause "headers already
    sent" crashes when SMTP fails.
  - knowledgeBaseRoutes.js:60 hardcodes createdby: 1 (first user) for uploads.
  - Auth middleware (auth.js:16) uses SECRETKEY; if unset, all authed routes
    fail closed but the many unauthenticated routes remain open.

M-04  ERROR HANDLING / CODE QUALITY (representative list)

  - StatCollect handlers return raw DB errors in HTTP responses

  - stage_register handlers return err.Error() to clients (documents.go:69,

  - Multiple ignored errors: assets/manager.go:127,158,184 (json.Unmarshal);

    results unused in uploads; enterprise handleGetEvent etc.
  - backend/main.go handleAlerts (688-692) seeds fake demo history - masks real
    anomaly detection results.
M-05  DEAD / UNUSED CODE
  - stage_register/go-backend/handlers/auth.go Register/Login are not routed
    (routes.go uses users.go handlers) - dead but still compiles and carries
    the weak secret logic; remove to reduce surface.
  - StatSpatial main.go:9 imports "statspatial/pkg/api" and main.go:55 calls

M-06  MISSING VALIDATION

  - appluancher login (AuthContext.tsx:64-68) posts {emailOrUsername,password};
